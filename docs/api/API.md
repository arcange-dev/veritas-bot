# API notes

Base path `/api/v1`. OpenAPI is served at `/api/schema/` and Swagger at `/api/docs/` when the
service is running (generated by `drf-spectacular`).

## Authentication

`Authorization: Bearer <supabase-access-token>`. Verified server-side: HS256 against
`SUPABASE_JWT_SECRET`, or RS256/ES256 against the project JWKS with a 5-minute cache and one
refetch on an unknown `kid`, then fail closed. Audience must be `authenticated`.

The token's `sub` maps to an `identity.Profile`. There is no separate password flow.

## Tenancy

Tenant routes are nested: `/api/v1/orgs/{org_id}/...`. The org is resolved from the URL (or the
`X-Org-Id` header) and the caller's active membership. **Not a member: 404, never 403**, so
resource ids cannot be enumerated.

## Errors

```json
{ "code": "spend_cap_exceeded", "detail": "Organization monthly cap of $50 would be exceeded.", "request_id": "9f2..." }
```

`detail` never contains a stack trace, a query, or a credential. `request_id` matches the
`X-Request-Id` response header and the server log line.

## Pagination

Cursor-based: `?page_size=50&cursor=...`, response `{"results": [...], "next": "..."}`. Offset
pagination is deliberately not offered on run, step or usage tables.

## Endpoints implemented

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/healthz` | public | Checks DB and Redis, 503 when the database is down |
| GET | `/api/schema/`, `/api/docs/` | public | OpenAPI and Swagger |
| GET | `/api/v1/orgs/{org}/projects/` | member | Own organisation only |
| POST | `/api/v1/orgs/{org}/projects/` | member, not viewer | `slug` derived from `name` if absent |
| GET | `/api/v1/orgs/{org}/projects/{id}/` | member | 404 across tenants |
| PATCH/DELETE | `/api/v1/orgs/{org}/projects/{id}/` | writer | |
| GET | `/api/v1/orgs/{org}/credentials/` | member | Returns `last4`, never the key |
| POST | `/api/v1/orgs/{org}/credentials/` | admin | `api_key` is write-only |
| POST | `/api/v1/orgs/{org}/credentials/{id}/test/` | admin | Runs the provider probe, persists status |
| DELETE | `/api/v1/orgs/{org}/credentials/{id}/` | admin | |

## Planned, not implemented

Runs and steps (`POST /orgs/{org}/runs/`, `GET /runs/{id}/steps/`), approvals
(`POST /approvals/{id}/decide/`), runner pairing (`POST /runners/pairing/`,
`POST /runners/pairing/claim/`), and the WebSocket channels `ws/runs/{run_id}/` and
`ws/runner/?device=&token=`. The runner client already speaks the planned protocol; the server
side of it does not exist yet.

## Runner protocol (v1)

Client to server: `hello` (version, os, arch, workspace roots). Server to client: `exec`
(argv, cwd, timeout, approval id), `fs.read|write|list`, `stop`. Client to server: `result`
(id, ok, data, error), `output` (session, stream, seq, data), `pong`. Frames carry `v: 1`;
additive changes only.
